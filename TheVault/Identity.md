- `Identity` columns are preferred for primary keys
- It's a special column that is generated automatically from an implicit sequence.
- To create a identity column, use `GENERATED ... AS IDENTITY clause`
	```sql
  >>> CREATE TABLE identity_example (
  >>> id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  >>> name TEXT
  >>> );
  CREATE TABLE
	```
	Adding `PRIMARY KEY` is not necessary for the sake of `identity` column
	```sql
  >>> INSERT INTO identity_example (name) VALUES ('hellor');
  INSERT 0 1

  -- query repeated 4 times

  >>> SELECT * FROM identity_example;
  id |  name
  ----+--------
    1 | hellor
    2 | hellor
    3 | hellor
    4 | hellor
  (4 rows)

	```

- Don't explicitly try to insert the `id` as it will throw error
	```sql
  >>> INSERT INTO identity_example (id, name) VALUES (5, 'hellor');
  ERROR:  cannot insert a non-DEFAULT value into column "id"
  DETAIL:  Column "id" is an identity column defined as GENERATED ALWAYS.
  HINT:  Use OVERRIDING SYSTEM VALUE to override.
	```

- If you absolutely need to insert an id explicitly, use the clause `OVERRIDING SYSTEM VALUE`
	```sql
  >>> INSERT INTO identity_example (id, name) OVERRIDING SYSTEM VALUE VALUES (5, 'hellor');
  INSERT 0 1
  >>> SELECT * FROM identity_example;
  id |  name
  ----+--------
    1 | hellor
    2 | hellor
    3 | hellor
    4 | hellor
    5 | hellor
  (5 rows)
  
  -- Now the original sequence haven't moved forward, so if the identity_column is PRIMARY KEY ( which doesn't allow duplicate keys ) an error will thrown, 
  -- otherwise duplicate keys would exist

  >>> INSERT INTO identity_example (name) VALUES ('hellor');
  ERROR:  duplicate key value violates unique constraint "identity_example_pkey"
  DETAIL:  Key (id)=(5) already exists.
  
  -- since we have added identity column as PRIMARY KEY, thus we have the error
  -- to resolve the error, we have to identify the implicit sequence and then use 
  -- setval to reset the sequence to the correct value.
  
  >>> SELECT pg_get_serial_sequence('identity_example', 'id');
      pg_get_serial_sequence
  --------------------------------
  public.identity_example_id_seq
  (1 row)
  
  -- pg_get_serial_sequence gives the name of sequence used by a particular table column, so now we have the name of the sequence, we can use setval on it

  >>> SELECT setval('public.identity_example_id_seq', (SELECT max(id) from identity_example));
  setval
  --------
        5
  (1 row)

  -- now we can insert the normal values and won't have the error

  >>> INSERT INTO identity_example (name) VALUES ('hellor');
  INSERT 0 1
  >>> INSERT INTO identity_example (name) VALUES ('hellor');
  INSERT 0 1
  >>> SELECT * FROM identity_example;
  id |  name
  ----+--------
    1 | hellor
    2 | hellor
    3 | hellor
    4 | hellor
    5 | hellor
    6 | hellor
    7 | hellor
  (7 rows)
	```
	It took a lot of effort to fix the problem, that's why, until **ABSOLUTELY NECESSARY**, don't explicitly insert values in `identity` column

- You can use clause `BY DEFAULT` instead of `ALWAYS` in `Identity` column. It will allow you to add values explicitly without adding extra clause of `OVERRIDING SYSTEM VALUE` to the `SQL query`, thus making it easy to break. It's advised **NOT TO** use `BY DEFAULT` clause
	```SQL
  >>> CREATE TABLE ex_id (
  >>> id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  >>> name text
  >>> );
  CREATE TABLE
  >>>
  >>> INSERT INTO ex_id (name) VALUES ('rgd');
  INSERT 0 1
  >>> INSERT INTO ex_id (id, name) VALUES (2, 'rgd');
  INSERT 0 1
  >>> SELECT * FROM ex_id;
  id | name
  ----+------
    1 | rgd
    2 | rgd
  (2 rows)

  >>> INSERT INTO ex_id (name) VALUES ('rgd');
  ERROR:  duplicate key value violates unique constraint "ex_id_pkey"
  DETAIL:  Key (id)=(2) already exists.
	```
	you can see, `BY DEFAULT` just makes it easy to break, to fix it, you have to again go all over the same procedure of getting the name of the `sequence` and then using `setval` to set the value of the sequence. So avoid using it.
